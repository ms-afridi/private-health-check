The math behind it (short version)

The model computes risk = sigmoid(w · x + b). Encryption can only add and multiply, so the curved sigmoid is replaced by a simple polynomial, 0.5 + a₁·z + a₃·z³, fitted to the range the model actually uses.

Honest limitations

  • This is a simulation of two parties in one app. The boundary is enforced in code, not by the network, and the patient's secret key is held in server memory for the demo.
  • The data is a small public dataset (UCI Heart Disease), not real patient data. The model is simple (logistic regression) and is not medical advice.
  • The hospital knows the model and sees the size of the data. Encryption protects the patient's values and the result, not the model.
  • Encrypted inference protects the data during computation. It does not by itself prevent attacks on the model such as membership inference. That is a research direction for the PhD.
Prototype for the PATAI research group application, built with FastAPI and TenSEAL (CKKS).
